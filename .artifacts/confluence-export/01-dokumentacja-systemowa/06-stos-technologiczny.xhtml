2. Uzasadnienie wyborów technologicznych i odrzucone alternatywy

Obszar decyzyjny

Wybrane rozwiązanie

Odrzucone alternatywy

Uzasadnienie architektoniczne wyboru

Stos serwerowy i język domeny

C# / .NET 10 LTS

Full-stack TypeScript (Node.js), C# + Godot

Większość 6-osobowego zespołu posiada doświadczenie w C# z wcześniejszych projektów; .NET 10 zapewnia silne typowanie rekordów, dojrzały serwer SignalR, EF Core oraz długoterminowe wsparcie LTS (wsparcie dla .NET 8 wygasa w listopadzie 2026 r.).

Protokół komunikacji czasu rzeczywistego

ASP.NET Core SignalR

Surowe gniazda WebSocket, WebRTC / PeerJS (P2P)

Architektura P2P w prototypie umożliwiała oszustwa i podglądanie kart przeciwnika. SignalR zapewnia natywne wsparcie dla autorytatywnego serwera, grup meczowych, automatycznego wznawiania połączeń i silnie typowanych hubów.

Technologia klienta webowego

React 19 + TypeScript + Vite

Czysty JS (Vanilla DOM z prototypu), Blazor WebAssembly

Czysty JS w prototypie prowadził do trudnego w utrzymaniu kodu imperatywnego i podatności XSS (innerHTML). React + TypeScript zapewnia bezpieczne, komponentowe renderowanie widoku MatchView przy zachowaniu niskiego rozmiaru paczki i łatwego wykorzystania stylów CSS z prototypu.

Strategia bazy danych

SQLite (S0–S3) → PostgreSQL (od S4)

PostgreSQL w kontenerze od pierwszego dnia

Wymuszenie instalacji i konfiguracji Dockera u wszystkich 6 osób w pierwszym tygodniu stanowiło ryzyko zablokowania startu prac. EF Core izoluje kod od dostawcy bazy, pozwalając na bezinwazyjną pracę na pliku SQLite i przejście na kontener PostgreSQL w Sprincie 4.

Narzędzie Spec-Driven Development

OpenSpec 1.15 + Konstytucja w .agents/

GitHub Spec Kit (specify-cli), BMAD

W przeprowadzonych testach porównawczych (04-badania-i-analizy/faza-1-porownanie.md) Spec Kit wykazał konflikty przy instalacji dla wielu narzędzi AI jednocześnie i generował blisko 10 tys. linii szablonów. OpenSpec instaluje się czysto dla wszystkich 5 narzędzi AI i posiada szybki walidator CLI dla potoku CI.

Kontrola zgodności kontraktów C# ↔ TS

Wspólna próbka JSON (match-view.sample.json)

Generator OpenAPI / NSwag, brak automatycznej kontroli

Główne komunikaty gry przechodzą przez SignalR, którego standard OpenAPI nie obejmuje. Złoty plik JSON generowany przez testy C# i weryfikowany kompilatorem TypeScript (tsc) daje 100% gwarancji wykrycia niezgodności bez narzutu zewnętrznych generatorów.

4. Polityka zarządzania wersjami i zależnościami

  1. Centralne zarządzanie pakietami NuGet (Central Package Management): Wszystkie wersje pakietów .NET są zdefiniowane w jednym pliku Directory.Packages.props w katalogu głównym. Projekty .csproj nie mogą deklarować własnych atrybutów Version.
  2. Deterministyczne instalacje npm: Zarówno katalog główny narzędzi, jak i projekt src/web posiadają zatwierdzone pliki package-lock.json. W potoku CI oraz skryptach startowych używane jest polecenie npm ci.
  3. Automatyczne aktualizacje bezpieczeństwa: Usługa GitHub Dependabot (.github/dependabot.yml) co tydzień sprawdza aktualizacje pakietów NuGet, npm oraz akcji GitHub, grupując poprawki z ekosystemów Microsoft i Aspire. Podatności o priorytecie wysokim i krytycznym są aktualizowane w czasie ≤ 7 dni (NFR-42).
