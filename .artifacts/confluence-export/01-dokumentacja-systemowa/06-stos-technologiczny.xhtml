Ten dokument opisuje stos technologiczny projektu RE:JOLTANCE. Wersje pochodzą z package.json i package-lock.json (stan na 21.11.2026). Wyjaśniamy też, dlaczego wybraliśmy dane technologie i kiedy wprowadzamy kolejne (technology roadmap).

Od 21.11.2026 całe repozytorium jest w TypeScript na Node.js (ADR-0015 (07-decyzje-adr/0015-backend-node-typescript.md)); wcześniej backend był w .NET (ADR-0001).

Skróty: SDD (Spec-Driven Development) to praca „najpierw specyfikacja, potem kod”. ADR (Architecture Decision Record) to zapis jednej decyzji architektonicznej.

2. Dlaczego te technologie i co odrzuciliśmy

Obszar decyzji

Wybór

Odrzucone alternatywy

Uzasadnienie

Język całego systemu

TypeScript na Node.js 24

C# / .NET 10 (pierwotny wybór, ADR-0001)

Kanon zasad gry jest w JS, więc silnik w TS można porównywać z prototypem w tym samym procesie. Kontrakty są jednym pakietem dla serwera i klienta. Jedno środowisko zamiast trzech (.NET, Node, Python). Kod C# był jeszcze mały, więc zmiana była tania (ADR-0015 (07-decyzje-adr/0015-backend-node-typescript.md)).

Komunikacja w czasie rzeczywistym

Socket.IO

surowe WebSockety (ws), WebRTC / PeerJS (P2P)

P2P w prototypie pozwalało oszukiwać i podglądać karty przeciwnika. Socket.IO daje autorytatywny serwer, pokoje, potwierdzenia odpowiedzi i automatyczne wznawianie połączeń, a jego zdarzenia typujemy z packages/contracts.

Serwer HTTP

Fastify

Express

Szybki, z wbudowanym testowaniem żądań bez sieci (app.inject) i dobrą obsługą TypeScript.

Klient webowy

React 19 + TypeScript + Vite

czysty JS z prototypu, Blazor

Czysty JS dał trudny w utrzymaniu kod imperatywny i podatność XSS (innerHTML). React bezpiecznie renderuje MatchView.

Baza danych

SQLite → PostgreSQL (od S4)

PostgreSQL w kontenerze od pierwszego dnia

Bez Dockera na laptopach na starcie; przejście w Sprincie 4 (ADR-0007 (07-decyzje-adr/0007-sqlite-potem-postgresql.md)).

Narzędzie do SDD

OpenSpec + konstytucja w .agents/

GitHub Spec Kit, BMAD

Spec Kit miał konflikty instalacji i generował ok. 10 tys. linii szablonów; OpenSpec instaluje się czysto i ma walidator do CI (04-badania-i-analizy/faza-1-porownanie.md).

XSS (Cross-Site Scripting) to atak polegający na wstrzyknięciu skryptu do strony. P2P (Peer-to-Peer) to komunikacja bezpośrednio między przeglądarkami, bez serwera.

4. Zasady zarządzania wersjami i zależnościami

  1. Jeden lockfile. Wszystkie pakiety repozytorium mają wspólny package-lock.json w katalogu głównym; CI i npm run setup używają npm ci.
  2. Nowa zależność npm = zgoda człowieka. Agent AI pyta przed dodaniem paczki (AGENTS.md, reguła 20); silnik i katalog kart nie mają zależności spoza repozytorium (test tools/architecture.test.ts).
  3. Automatyczne aktualizacje bezpieczeństwa. Dependabot (.github/dependabot.yml) co tydzień sprawdza npm i co miesiąc akcje GitHub. Podatności wysokie i krytyczne aktualizujemy w ciągu ≤ 7 dni (NFR-42). Nowej głównej wersji TypeScript nie podnosimy automatycznie.
