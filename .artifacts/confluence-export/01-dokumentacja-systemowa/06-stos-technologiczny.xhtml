2. Dlaczego te technologie i co odrzuciliśmy

Obszar decyzji

Wybór

Odrzucone alternatywy

Uzasadnienie

Serwer i język domeny

C# / .NET 10 LTS

Full-stack TypeScript (Node.js), C# + Godot

Większość zespołu zna C# z wcześniejszych projektów. .NET 10 daje silnie typowane rekordy, dojrzały SignalR, EF Core i długie wsparcie LTS. Wsparcie .NET 8 kończy się w listopadzie 2026 r.

Komunikacja w czasie rzeczywistym

ASP.NET Core SignalR

Surowe WebSockety, WebRTC / PeerJS (P2P)

P2P w prototypie pozwalało oszukiwać i podglądać karty przeciwnika. SignalR wspiera autorytatywny serwer, grupy meczowe, automatyczne wznawianie połączeń i silnie typowane huby.

Klient webowy

React 19 + TypeScript + Vite

Czysty JS (Vanilla DOM z prototypu), Blazor WebAssembly

Czysty JS w prototypie dał trudny w utrzymaniu kod imperatywny i podatność XSS (innerHTML). React + TypeScript bezpiecznie renderuje MatchView z komponentów. Paczka zostaje mała, a style CSS z prototypu łatwo przenieść.

Baza danych

SQLite (S0–S3) → PostgreSQL (od S4)

PostgreSQL w kontenerze od pierwszego dnia

Gdyby 6 osób musiało w pierwszym tygodniu zainstalować i skonfigurować Dockera, start prac mógłby się zablokować. EF Core ukrywa szczegóły dostawcy bazy. Pracujemy więc na pliku SQLite, a w Sprincie 4 przechodzimy na kontener PostgreSQL.

Narzędzie do SDD

OpenSpec 1.15 + Konstytucja w .agents/

GitHub Spec Kit (specify-cli), BMAD

Porównaliśmy narzędzia (04-badania-i-analizy/faza-1-porownanie.md). Spec Kit miał konflikty przy instalacji dla kilku narzędzi AI naraz i generował prawie 10 tys. linii szablonów. OpenSpec instaluje się czysto dla wszystkich 5 narzędzi AI i ma szybki walidator CLI do CI.

Zgodność kontraktów C# ↔ TS

Wspólna próbka JSON (match-view.sample.json)

Generator OpenAPI / NSwag, brak automatycznej kontroli

Główne komunikaty gry idą przez SignalR, a OpenAPI go nie obejmuje. Testy C# generują wzorcowy plik JSON, a kompilator TypeScript (tsc) go sprawdza. To pewnie wykrywa każdą niezgodność bez dodatkowych generatorów.

XSS (Cross-Site Scripting) to atak polegający na wstrzyknięciu skryptu do strony. P2P (Peer-to-Peer) to komunikacja bezpośrednio między przeglądarkami, bez serwera.

4. Zasady zarządzania wersjami i zależnościami

  1. Centralne zarządzanie pakietami NuGet (Central Package Management). Wszystkie wersje pakietów .NET są w jednym pliku Directory.Packages.props w katalogu głównym. Pliki .csproj nie mogą deklarować własnego atrybutu Version.
  2. Powtarzalne instalacje npm. Katalog główny i projekt src/web mają zatwierdzone pliki package-lock.json. CI i skrypty startowe używają polecenia npm ci.
  3. Automatyczne aktualizacje bezpieczeństwa. GitHub Dependabot (.github/dependabot.yml) co tydzień sprawdza aktualizacje pakietów NuGet, npm i akcji GitHub. Grupuje poprawki z ekosystemów Microsoft i Aspire. Podatności o priorytecie wysokim i krytycznym aktualizujemy w ciągu ≤ 7 dni (NFR-42).
