Ta mapa pomaga ci poruszać się po kodzie RE:JOLTANCE. Jest dla członków zespołu i dla agentów AI. Zanim zmienisz jakiś moduł, przeczytaj tę mapę i plik README.md w katalogu modułu (packages/<pakiet>/README.md albo apps/<aplikacja>/README.md).

SDD (Spec-Driven Development) to nasz sposób pracy: najpierw specyfikacja, potem kod. Ta strona należy do etapu Realizacja.

1. Architektura i kierunek zależności

Całe repozytorium to jeden projekt npm (workspaces) w TypeScript na Node.js 24 (ADR-0015 (07-decyzje-adr/0015-backend-node-typescript.md)).

none

Reguła zależności: importy prowadzą tylko z góry na dół, a klient web importuje wyłącznie packages/contracts. Pilnuje tego ESLint (eslint.config.js) i test tools/architecture.test.ts przy każdym npm run verify.

3. Przewodnik praktyczny: „Gdzie dodać nową funkcję?”

Co chcesz zrobić?

Które pliki zmienić?

Ryzyko

Zalecany skill agenta AI

Dodać nową kartę lub zmienić statystyki istniejącej (z istniejących słów DSL)

1. Zmień game/cards.js w repo PanCoto/rejoltance-prototype (źródło prototypu)
2. Dociągnij zmiany: git subtree pull --prefix=prototype https://github.com/PanCoto/rejoltance-prototype.git main
3. Uruchom npm run cards
4. Uruchom npm test

Niski

rj-add-card (../04-system-agentow-ai/02-katalog-rol-i-wbudowanych-skilli.md)

Dodać do DSL nowe słowo kluczowe, wyzwalacz lub akcję

1. Dopisz regułę R-nn w openspec/specs/
2. Dodaj słowo do packages/content/src/vocabulary.ts
3. Zaimplementuj obsługę w packages/engine
4. Napisz test Rnn_... w packages/engine/test

Średni

rj-add-rule-test (../04-system-agentow-ai/02-katalog-rol-i-wbudowanych-skilli.md)

Zaimplementować lub zmienić regułę mechaniki gry (R-nn)

1. Napisz test Rnn_... w packages/engine/test/
2. Zaimplementuj logikę w packages/engine/src/engine.ts (albo w osobnym pliku w silniku)
3. Zaktualizuj status w 03-indeks-regul-r-nn.md

Średni

rj-add-rule-test (../04-system-agentow-ai/02-katalog-rol-i-wbudowanych-skilli.md)

Zmienić strukturę MatchView, Intent lub DomainEvent

1. Zapisz decyzję w ADR (07-decyzje-adr/)
2. Zmień typ albo schemat w packages/contracts/src/
3. Popraw miejsca, które wskaże npm run typecheck (silnik, serwer, klient)
4. Odśwież próbkę: UPDATE_CONTRACT_SAMPLES=1 npm test — wszystko w jednym PR!

Wysoki (zmiana zamrożonego kontraktu)

rj-write-adr (../04-system-agentow-ai/02-katalog-rol-i-wbudowanych-skilli.md)

Dodać zdarzenie Socket.IO lub endpoint REST

1. Dopisz typ zdarzenia w packages/contracts/src/protocol.ts
2. Obsłuż je w apps/server/src/app.ts
3. Dodaj test w apps/server/test/
4. Zaktualizuj 09-kontrakty-i-api.md
