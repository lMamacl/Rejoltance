Kontekst i problem

Instrukcja pracowni wymaga przeglądów kodu w Bitbucket PB (DC 8.14.4) i raportowania przez Jira/Bitbucket. [V] Zespół chce GitHub Actions, GitHub Pages dla prototypu i integracji narzędzi AI (Copilot, agenci), które najlepiej działają z GitHubem. [V] Bitbucket DC nie ma Pipelines (CI trzeba by stawiać osobno). [Z]

Decyzja

W kontekście wymogów uczelni i potrzeby CI oraz narzędzi AI, wybieramy **GitHub jako miejsce pracy (PR, review, CI) i automatyczny mirror gałęzi main, develop oraz tagów sprint-* do Bitbucket PB** zamiast pracy w Bitbucket, aby mieć działające CI od pierwszego dnia, akceptując, że review trzeba udokumentować linkiem do PR w zgłoszeniu Jira (do potwierdzenia z prowadzącym).

Konsekwencje

Pozytywne

  • CI, Pages, Dependabot, szablony PR/issue działają bez dodatkowej infrastruktury.

Negatywne / ryzyka

  • Sekret BITBUCKET_TOKEN musi ustawić admin repo; bez niego mirror jest pomijany (nie psuje CI).
  • Jeśli prowadzący wymaga review w Bitbucket — wracamy do tego ADR (nowy ADR zastępujący).
